# MAGLUMI Snibe X8 - DLL-драйвер ЛИС

Решение под .NET 9 повторяет архитектуру `SysmexCS2000Ready`. Приборная DLL реализует `IAnalyzerDriver`; общий Host загружает её по `DllPath` и вызывает `Initialize`, `RunAsync`, `Stop`, `Dispose`. TCP listener, разбор HL7, запросы заданий и преобразование результатов находятся в DLL.

## Структура

- `src/AnalyzerService.Host`, `AnalyzerService.Contracts`, `AnalyzerService.Transport`, `AnalyzerService.LisDatabase`, `AnalyzerService.ResultFiles` - точные копии соответствующих компонентов Sysmex, без изменений исходников и файлов проектов.
- `src/Maglumi.Snibe.Driver` - DLL MAGLUMI X8, MLLP/HL7-кодеки и адаптер результатов к файловому интерфейсу ЛИС.
- `configs/MaglumiSnibe.json` - конфигурация в существующей схеме `AnalyzerSettings`.
- `tests/Maglumi.Snibe.Driver.Tests` - автономный исполняемый набор проверок и TCP-эмулятор X8; рабочая SQL-база не требуется.
- `tests/shared-components.sha256.json`, `tests/VerifySharedComponents.ps1` - контроль неизменности общих компонентов, включая сравнение с соседним Sysmex, если он доступен.
- `docs` - исходная документация производителя, сохранённая без изменений.

Новый драйвер не содержит преобразований кодов групп, десятичных масштабов или low/med из Sysmex. `LisDBProvider.GetOrder` и `TranslateResultCode` вызываются без изменения общих SQL-запросов.

## Поддерживаемый интерфейс

Основание: `docs/GR942023110165121422 (1).pdf`, **Interface Specifications of MAGLUMI X8 Software System**, разделы 2-5, 7-9, 11. Старые руководства ASTM/COM из `docs` описывают другой интерфейс.

- ЛИС - TCP-сервер; X8 - TCP-клиент. `IPaddress` задаёт локальный адрес сервера ЛИС, `Port` - порт listener, а не адрес прибора.
- HL7 2.5, UTF-8 без BOM, разделители `|^~\&`. Каждый сегмент заканчивается CR. Кадр: `0B + HL7 + 1C 0D`.
- Принимаются разделённые между TCP-чтениями кадры и несколько кадров в одном чтении. Допускается несколько HL7-сообщений в одном MLLP-кадре. Максимум кадра - 4 МиБ; ожидание продолжения начатого кадра - 30 секунд. Бездействующее соединение без начатого кадра остаётся открытым.
- После разрыва/ошибки сеанса listener ожидает новое подключение. Неполный кадр не преобразуется в результат; причина фиксируется в Error. Полный кадр с ошибкой HL7 сохраняется в очереди для диагностики.
- Исходящие поля HL7 экранируются, кириллица пациента передаётся в UTF-8.
- ACK для `OUL^R22` не отправляется: спецификация требует `MSH-15/16=NE` и явно указывает отсутствие ответа.

### Задания

Входной `TSREQ` содержит `QPD|TSREQ||SampleId^Sequence^Rack^Position|Priority`. По штрихкоду `QPD-3.1` выполняется `GetOrder`. Ответ - `OML^O33`, при наличии исследований: `MSH`, `PID`, `SPM`, `ORC|NW`, по одному `OBR` на уникальный код канала X8. Возвращаются только исследования, выбранные существующим SQL-фильтром незавершённых заданий.

ФИО, дата рождения, пол и вычисленный возраст берутся из `LisOrder`; пол переводится в коды X8 `1/2/3`. Штрихкод, внутренний номер, штатив и позиция переносятся из запроса; в `SPM-2.3` оставляется пустой компонент QC ID. Пустой заказ/отсутствие пациента возвращается как `MSH + SPM`, без `PID/ORC/OBR`. Сбой SQL не подменяется сообщением об отсутствии заказа: ответ не отправляется, ошибка записывается в журнал.

Запрос только по позиции или внутреннему номеру без штрихкода не обслуживается: общий `LisDBProvider` ищет по RID. Расширять эту логику без изменения общего компонента нельзя.

В таблицах спецификации `QPD-4` и `ORC-7` приоритеты определены как `0` (обычный) / `1` (срочный), но в примерах встречается `2`. Драйвер использует таблицы, отклоняет `2` с явной ошибкой. Перед внедрением нужно подтвердить значения в реальном TSREQ прибора.

Тип материала `SPM-4` отсутствует в общем `LisOrder`, поэтому исходящий ответ оставляет его пустым. Сыворотка/плазма не подставляются автоматически. Приём такого ответа и настройку материала необходимо проверить на X8 при приёмке. Активная рассылка заказов, `RF` и опрос результатов по инициативе ЛИС не входят в эту реализацию, как и в исходном сценарии Sysmex.

### Результаты

Принимается `OUL^R22`. Пациент определяется по `SPM-11=P`, штрихкод - `SPM-2.1`; контроль - по `SPM-11=Q`, QC ID - `SPM-2.3`. Контроли сохраняются исходными байтами в `QualityControl` и не создают `.res/.ok`. Смешанный кадр с пациентами и QC сохраняется также в `QualityControl`, а пациентские группы обрабатываются очередью.

Полный пациентский кадр сохраняется до преобразования. Общая `RawResultQueue` создаёт `archive`, `errors`, `QualityControl`, возобновляет обработку `.raw` после запуска. `ResultHandlerStatus=false` отключает преобразование, но сохраняет входящие `.raw` и QC. Из-за требования оставить `ResultFiles` неизменённым префиксы имён сырых файлов остаются `SYS2000` / `SYS2000_QC`; содержимое этих файлов - точные байты X8, это не признак протокола Sysmex.

Для каждого пациентского `SPM` создаётся отдельная пара `<sourceId>_<номер>.res/.ok`. Формат и позиции полей совпадают с адаптером Sysmex: строка `O`, строки `R`, Windows-1251, CRLF, сначала `.res`, затем `.ok`, запись через временное имя. Маркер прибора в поле оператора - `MAGLUMI^`; код прибора берётся из `AnalyzerCode`. Время результата берётся из `OBX-19`. Наличие `.ok` предотвращает повторное создание той же пары при повторной обработке одного `.raw`; повторная самостоятельная передача прибором считается новым сообщением.

Число берётся из `OBX-5.1` с сохранением всех десятичных знаков, заменяется только точка на запятую. Значение `3.5600` становится `3,5600`. `OBX-5.2` (качественный компонент) и единицы сохраняются в исходном сообщении и журнале; в числовую строку ЛИС они не подставляются. Передаются исходные флаги `N/H/L/HH/LL` и пустой флаг. Допускается только финальный статус `OBX-11=F`.

Качественный результат без числа, пороговые `<`/`>`, научная запись, неизвестный код PSMV2, неизвестный флаг, предварительный статус, тревога в `NTE-3`, неверное время и несовпадение кодов/номеров `OBR/OBX` приводят к `errors`, без создания новых `.ok` для этого сообщения. Поддержка таких значений в файле требует подтверждения возможностей принимающей ЛИС. В PDF есть пример с `OBR=TSH` и `OBX=TG`; драйвер отклоняет такое несоответствие, не угадывает правильный код.

## Настройка

Пример конфигурации по умолчанию имеет `ActiveStatus=false`. Перед запуском:

1. Указать локальные `IPaddress`/`Port`, настроить X8 на подключение к ним.
2. Заполнить `ConnectionString`, `AnalyzerCode`, `AnalyzerConfigurationCode` для реальной ЛИС. Пример не содержит рабочего пароля.
3. Настроить соответствия каналов X8 и PSMV2 в существующей таблице `konvana`.
4. Проверить `ResultsFolder`, `OutputFolder` и права учётной записи службы на SQL, журналы и файлы.
5. Установить `ActiveStatus=true`; оставить `Protocol=MAGLUMI_X8_HL7`, `ConnectionType=TCPIP`.

Относительный `ResultsFolder` вычисляется общим компонентом как `<каталог службы>/<AnalyzerName>/<ResultsFolder>`, относительный `OutputFolder` - от каталога службы. Параметры журналов и жизненный цикл остаются такими же, как в Sysmex. SQL-вызовы остаются синхронными с исходными таймаутами общего компонента; остановка ожидает завершения текущей обработки файла.

## Сборка и проверка

Из каталога `Maglumi Snibe`:

```powershell
dotnet build AnalyzerService.sln --maxcpucount:1 --disable-build-servers
dotnet run --project tests/Maglumi.Snibe.Driver.Tests --no-build
./tests/VerifySharedComponents.ps1
./package.ps1
./tests/PublishedPackageSmoke.ps1
```

Открыть решение можно и в Visual Studio с поддержкой SDK .NET 9. Публикация создаёт `publish/AnalyzerService/AnalyzerService.Host.exe` (однофайловый Host, требуется .NET 9 Runtime) и `drivers/MaglumiSnibe` только с DLL драйвера и `.deps.json`. Общие библиотеки включаются в Host, разделяются через неизменённый `DriverLoadContext` и не копируются в каталог драйвера.

Для повторной публикации с уже восстановленными зависимостями той же платформы можно использовать `./package.ps1 -NoRestore`.

Автотесты проверяют задания, отсутствие заказа, ошибку БД, точность значений, формат файлов, QC, восстановление очереди, ошибки, TCP-фрагментацию, переподключение, отмену/остановку и идентичность загруженных общих сборок. Эмулятор подставляет только ответы БД через зависимости самой DLL; общий `LisDBProvider` не меняется. Smoke-тест запускает копию опубликованного Host с loopback-конфигурацией и проверяет загрузку DLL, приём пациентского/QC кадров и точность сохранённых байтов, без рабочей SQL-базы.

Приёмка на реальном X8 должна подтвердить: реальный TSREQ (приоритет/идентификация), появление задания с несколькими тестами и отсутствие заказа, допустимость пустого `SPM-4`, соответствия кодов/единиц, точность значений и флаги, QC, ручную повторную передачу и восстановление связи. Подключение к рабочей БД и реальному прибору автоматическими тестами не проверяется.
