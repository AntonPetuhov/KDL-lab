# UnityQcExporter

Служба Windows переносит готовые `*.csv` из верхнего уровня папок `Ready` в одну папку импорта Unity. Один цикл на прибор запускается сразу и повторяется через заданный интервал после завершения прохода. Содержимое CSV переносится побайтно. Производитель должен закрыть временный файл и переименовать его в уникальное конечное имя `.csv`. Одинаковые имена у разных приборов допустимы. В выходной папке получится, например, `SysmexCS2000__qc-001.csv`.

## Пример

В `Examples/SysmexQC_20261116_1030.csv` две строки из одного исходного сообщения `Unity/QC sysmex/SYS2000_QC_QC___CtlN507945_202611160729476298933.raw`. Образец в кадре обозначен `QC   CtlN507945`. Значения кодов 652 и 882 равны 177,7 и 126,8. Время 16.11.2026 10:30 записано с секундами 00, поскольку прибор передал только минуты. Записи в ASCII, разделитель |, заголовка нет. Порядок полей — анализатор, лот контрольного материала, уровень, тест, результат, время, комментарий. Комментарий пуст.

Файл демонстрационный. Значения DEMO-CS2000, DEMO-LOT-N и DEMO-N обозначают условные настройки. Для импорта в лаборатории согласуйте реальные ID, лот, уровень и оба кода теста с настройками канала Unity. В файле нет сведений о партии или сроке годности реагента. Тестовый файл хранится вне очереди.

## Сборка и настройка

Откройте `UnityQcExporter.sln` в Visual Studio с поддержкой .NET 10. Опубликуйте проект с профилем WindowsFolder либо выполните `dotnet publish UnityQcExporter.csproj -p:PublishProfile=WindowsFolder`. Перенесите весь каталог `bin/Release/publish/win-x64` на сервер в отдельную постоянную папку. Профиль включает Runtime.

1. В `exporter.json` рядом с EXE укажите `UnityOutputFolder` (локальный путь или UNC, например `"\\\\unity-server\\qc-import"`) и интервал `PollSeconds` (по умолчанию 180).
2. Для каждого источника укажите постоянный уникальный `Id`, существующий `ReadyFolder` и `Unity: true`. Относительные пути отсчитываются от каталога EXE. Поставляемый пример выключен. При запуске служба подбирает также ранее накопленные готовые CSV. После изменения JSON перезапустите службу.
3. Настройте подбор в Unity по маске `*.csv`. Предоставьте аккаунту службы права изменения в активных Ready и назначения. Для UNC нужны права общей папки и NTFS. Используйте на каждом входе один экспортёр и зарезервируйте временные имена `*.csv.uploading` за ним.
4. Для первой проверки задайте локальные тестовые пути, запустите EXE и скопируйте пример в Ready. Проверьте байты выходного файла и архив. Закройте консоль Ctrl+C перед запуском службы.

Для установки из PowerShell администратора (пример пути):

```powershell
New-Service -Name UnityQcExporter -BinaryPathName '"C:\Services\UnityQcExporter\UnityQcExporter.exe"' -StartupType Automatic
Start-Service UnityQcExporter
```

## Доставка, перезапуск и диагностика

Служба копирует CSV под временным именем в каталоге назначения. Затем переносит исходный CSV в `Ready/.unity-export/Publishing`, открывает файл для импорта переименованием в `.csv` и архивирует локальную копию в `Ready/.unity-export/Sent`. Архив хранит имя уже переданного пакета даже после того, как Unity забрала файл. Размер архива растёт с объёмом обмена. Имя файла в пределах прибора должно быть уникальным для каждой новой выгрузки.

Если ресурс недоступен, очередь повторяет попытку в следующем проходе. При перезапуске сначала восстанавливаются операции Publishing. Если после прерывания в папке Unity отсутствуют и временный, и окончательный файл, невозможно установить, успела ли Unity забрать CSV. Файл остаётся в Publishing для сверки. При подтверждённом импорте перенесите его в Sent при остановленном экспортёре. Если установлено, что импорта не было, верните его в Ready для повторной доставки. Конфликты имён также требуют сверки. Публикация в папку подтверждает доступность файла для импорта, а успешный импорт проверяется в Unity.

Сообщения видны в консоли. При работе как Windows Service ошибки и предупреждения доступны в журнале Windows «Приложение». Для обычных рабочих сообщений можно включить уровень Information у провайдера EventLog.
