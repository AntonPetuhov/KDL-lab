# Analyzer Configuration Service - Sysmex CS-2000i Host Online

Решение под .NET 9 содержит драйвер Sysmex Host Online. Служба знает только `IAnalyzerDriver`: она загружает DLL, передаёт JSON и логгер, вызывает `RunAsync` и при остановке `Stop`. Конкретный транспорт выбирает и запускает сама DLL. Sysmex-драйвер использует общий `TcpHost` из библиотеки `AnalyzerService.Transport`; будущий драйвер может использовать COM-порт или файловый обмен без изменений в Host. ASTM из решения удалён.

## Каталоги и конфигурация

- `configs/SysmexCS2000.json` - единственная активная конфигурация; `configs/examples/SysmexCS2000i.json` - отключённый пример.
- `src/AnalyzerService.Host` - Windows Service, загрузка DLL, управление жизненным циклом и файловые журналы; сетевых классов в Host нет.
- `src/AnalyzerService.Contracts` - общие интерфейсы и модель существующего JSON.
- `src/AnalyzerService.Transport` - повторно используемый TCP-host для DLL, которым нужна сеть.
- `src/AnalyzerService.LisDatabase` - зависимость Sysmex-драйвера для запроса пациента и исследований в БД ЛИС.
- `src/AnalyzerService.ResultFiles` - зависимость Sysmex-драйвера для `.raw`, `archive`, `errors` и `QualityControl`.
- `src/SysmexCS2000.HostOnline.Driver` - владеет TCP listener, кодеком R221/S221/D121/D221 и преобразованием результатов в файлы ЛИС.

Для каждого активного **TCP-прибора** требуется отдельная пара `IPaddress`/`Port`; Host эти поля не проверяет. Общий валидатор Host проверяет только `AnalyzerName`, `Isdll` и `DllPath`; Sysmex-драйвер проверяет свои TCP, БД и файловые поля при `Initialize`. `ResultsFolder` из JSON используется без добавления новых полей: при относительном пути это `<каталог службы>/<AnalyzerName>/<ResultsFolder>`. Пациентские сообщения сохраняются по одному `.raw` на полученную передачу образца; выделенный поток создаёт `.res/.ok` и перемещает исходник в `archive` либо `errors`. Контроли качества сохраняются как исходные байты в `QualityControl` и в формат ЛИС не преобразуются.

## Задания R221

Перед отправкой S221 код ЛИС вида `392` приводится к коду группы `390`: согласно Host Online PDF третья цифра кода задания равна `0`. Повторные коды одной группы объединяются. ФИО транслитерируется в ASCII и ограничивается 15 символами; поле `ID Information` сохраняет признак из R221 (`B` для штрихкода). В S221 есть только 15-символьное поле имени пациента; передать дату рождения и пол этим форматом невозможно.

`LisDBProvider` пишет в протокольный журнал каждого кандидата из `bestall`: исходный тест, сопоставленный код прибора, статус, число попыток, наличие результата и причину включения/исключения. Это позволяет выяснить, почему SQL вернул один код, когда в ЛИС ожидались два. Фильтр незавершённых исследований сохранён: автоматически включать уже выполненные тесты опасно.

На стенде 02.10.2026 десять запросов R221 не получили S221: имена пациентов содержали цифру `8`, а прежняя ASCII-проверка её запрещала. Теперь цифры в имени допускаются; запрос, позиция штатива и ответ журналируются отдельно. Реальный прогон штатива после исправления требуется повторить.

## Разбор результатов D121/D221

Сырые кадры по-прежнему сохраняются без изменений. Кодек восстанавливает десятичный масштаб по таблице кодов Host Online из `2_5197664667366890338.pdf` (стр. 47/53) для кодов, встретившихся на стенде. Например, `39100781` означает `0.781`, а `392  286` — `28.6`; код `392` представляет процент с одним десятичным знаком. При записи `.res` числовой результат округляется до одного знака и записывается с запятой (`28,6`). Значения `*****`, `/////`, `+++++`, `-----`, `XXXXX` не выдаются в ЛИС как числа. Если в БД сопоставлен новый код без подтверждённого масштаба, файл уходит в `results/errors`, чтобы не передать неверное значение. При настройке новых тестов следует сверить Assay Group Settings прибора с форматом в документации и дополнить справочник кодов.

В Protocol сохраняется точный `RX:`/`TX:` текст, а для D121/D221 дополнительно записываются тип сообщения, штатив, позиция, образец и разобранные значения/флаги. Пояснения во всех журналах помечаются `Info:` и сдвигаются вправо; ошибки помечаются `Error:`.

Результаты low с кодами `872` и `662` являются повторным измерением соответствующих тестов med `882` и `652`. При поиске сопоставления с PSMV2 обработчик использует соответственно `882` и `652`; исходный код, значение и весь сырой кадр остаются без изменений. Если прибор отправил и med, и low, для обоих создаются отдельные строки результата с одним кодом теста ЛИС; порядок строк соответствует порядку в D-сообщении.

## Сборка и публикация

Откройте `AnalyzerService.sln` в Visual Studio 2022 с установленным SDK .NET 9 и выполните **Build Solution**. Для готового каталога запустите в PowerShell из корня проекта `./package.ps1`. Скрипт публикует `publish/AnalyzerService/AnalyzerService.Host.exe` с общими библиотеками в однофайловом пакете (для запуска требуется установленный .NET 9 Runtime) и отдельную папку `publish/AnalyzerService/drivers/SysmexCS2000HostOnline` только с `SysmexCS2000.HostOnline.Driver.dll` и `SysmexCS2000.HostOnline.Driver.deps.json`. `configs/SysmexCS2000.json` должен лежать в `publish/AnalyzerService/configs`.

### Изоляция зависимостей драйверов

Служба и DLL разделяют `AnalyzerService.Contracts`, `AnalyzerService.Transport`, `AnalyzerService.LisDatabase` и `AnalyzerService.ResultFiles`. Они публикуются вместе с Host; `DriverLoadContext` возвращает для этих имён сборки основного контекста. В `AnalyzerRuntime` по-прежнему нет транспортных вызовов: ссылки Host служат упаковке, а выбор TCP, COM или файлового обмена остаётся за драйвером. Пакет SQL Client входит в зависимости Host; нативные библиотеки включаются в однофайловый пакет с извлечением при запуске. Если будущему драйверу понадобятся собственные библиотеки, их размещение и правила загрузки потребуется явно добавить в пакет и `DriverLoadContext`.

Скрипт публикует драйвер во временный каталог, а затем переносит в `drivers` только его DLL и `.deps.json`. Скопируйте весь готовый каталог `publish/AnalyzerService`; отдельные сборки `AnalyzerService.*` в `drivers` помещать не нужно.

Для нового прибора реализуйте `IAnalyzerDriver` в отдельной DLL: `Initialize` проверяет собственные поля JSON, `RunAsync` запускает нужный обмен и возвращает задачу полного рабочего цикла, `Stop` разблокирует ожидания, `Dispose` освобождает ресурсы. Ссылку на DLL укажите в существующем `DllPath`. Добавлять ссылку на транспорт или протокол в Host не нужно. Папка `drivers/common` автоматически не просматривается.

Проверки: `dotnet build AnalyzerService.sln --maxcpucount:1`, `dotnet run --project tests/SysmexCS2000.HostOnline.Driver.Tests` и после публикации `./tests/PublishedPackageSmoke.ps1`. Последний скрипт создаёт временную копию пакета, запускает Host с loopback TCP и проверяет приём контрольного кадра; боевую конфигурацию он не меняет. После установки службы её учётной записи нужны доступ к БД ЛИС и права записи в `ResultsFolder`, `OutputFolder` и каталоги журналов.

DLL в папке `drivers` - управляемый плагин проекта, а не документированная фирменная DLL производителя. В текущем коде вызова внешней native DLL Sysmex нет. Для будущего прибора создайте DLL с реализацией `IAnalyzerDriver`, поместите её с `.deps.json` в отдельную подпапку `drivers`, укажите путь в `DllPath`; запуск TCP/COM/файлового обмена полностью останется в плагине.

ACK/NAK поверх TCP для Host Online в этой версии не добавлялись: этот режим ранее был отложен до проверки на анализаторе.
